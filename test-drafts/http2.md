# HTTP/2

## 한 줄 요약

HTTP/1.1의 병목은 대역폭이 아니라 **커넥션당 한 번에 하나**라는 제약이었다.
HTTP/2는 그걸 커넥션 하나 위의 스트림 다중화로 푼다.

## HTTP/1.1이 막혔던 자리

- 요청 하나가 끝나야 다음이 나간다 (head-of-line blocking)
- 브라우저가 도메인당 커넥션 6개를 여는 걸로 우회했고, 그래서 이미지 스프라이트나
  도메인 샤딩 같은 편법이 관행이 됐다
- 헤더가 매 요청마다 평문으로 반복된다. 쿠키가 크면 본문보다 헤더가 크다

## HTTP/2가 바꾼 것

**바이너리 프레이밍.** 텍스트 줄 단위가 아니라 프레임 단위로 자른다. 프레임마다
스트림 ID가 붙어서 뒤섞여 도착해도 재조립된다.

**멀티플렉싱.** 커넥션 하나에 스트림 여러 개. 커넥션 6개가 필요 없어지고,
위의 편법들도 같이 필요 없어진다.

**HPACK 헤더 압축.** 정적 테이블 + 동적 테이블 + 허프만. 반복되는 헤더는 인덱스
번호 하나로 줄어든다.

**서버 푸시.** 요청하지 않은 리소스를 미리 보낸다 — 캐시와 어긋나는 문제가 커서
실제로는 거의 안 쓰이고, 지금은 사장된 기능에 가깝다.

> [!NOTE]
> gRPC가 HTTP/2를 깔고 앉는 이유가 멀티플렉싱과 스트리밍이다.

> [!info] 아직 확인이 덜 된 것
> TCP 레벨 head-of-line blocking은 HTTP/2로도 안 풀린다. 그게 QUIC(HTTP/3)이
> 나온 이유인데, 이 문단은 더 확인해야 한다.
