# 가상 메모리와 페이징

## 핵심

프로세스는 자기가 메모리를 독차지하고 있다고 믿는다. 그 믿음을 유지시켜 주는 게
가상 메모리다. 프로세스가 보는 주소는 가상 주소고, 그걸 실제 물리 주소로 바꿔주는
것은 MMU다.

바꾸는 단위가 페이지다. 보통 4KB. 가상 주소 공간을 페이지로 자르고, 물리 메모리를
같은 크기의 프레임으로 자른 다음, 페이지 테이블에 "이 페이지는 저 프레임"을 적어둔다.
연속된 가상 주소가 물리적으로는 흩어져 있어도 되는 이유가 이것이다.

페이지 테이블을 매번 메모리에서 읽으면 주소 변환마다 메모리 접근이 한 번씩 더 생긴다.
그래서 최근 변환 결과를 캐시하는 TLB가 MMU 안에 있다.

### 페이지 폴트

접근한 페이지가 물리 메모리에 없으면 MMU가 폴트를 올린다. 커널이 그걸 받아서
디스크에서 해당 페이지를 올리고, 페이지 테이블을 갱신하고, 멈췄던 명령을 다시
실행시킨다. 프로세스 입장에서는 명령 하나가 오래 걸린 것으로만 보인다.

폴트가 잦아지면 실제로 일하는 시간보다 페이지를 나르는 시간이 길어진다. 그 상태를
스래싱이라고 부른다.

## 한 줄 정리

메모리를 페이지 단위로 잘라 필요한 것만 올려두고 없으면 그때 가져오는 것 — 그래서
물리 메모리보다 큰 주소 공간이 성립한다.
